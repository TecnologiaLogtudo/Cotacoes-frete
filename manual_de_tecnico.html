Manual do Usuário - LogTudo Cotações

Atualizado com o estado atual do app (frontend React, API FastAPI, fila RQ/Redis e automação Playwright).

Este manual está organizado por responsabilidades para facilitar manutenção e operação diária. Cada bloco usa uma tonalidade suave para indicar a área principal responsável.

1) Visão geral do sistema

Responsável: Operação
  • O sistema recebe uma planilha .xlsx, cria um job assíncrono e processa os registros no portal LogTudo.
  • A interface web permite iniciar execução, acompanhar progresso em tempo real e consultar logs detalhados.
  • A automação usa Playwright e roda no worker, desacoplando interface e processamento pesado.

2) Funcionalidades implementadas no app

Responsável: Plataforma

2.1 Frontend (tela principal)

  • Abas de navegação: Processamento, Logs e link para este manual.
  • Campos de entrada: Usuário, Senha, Data da cotação e upload de planilha.
  • Botão para mostrar/ocultar senha na interface.
  • Persistência local no navegador (localStorage) para usuário, senha e data da cotação.
  • Envio do job com botão Iniciar e reset visual do estado com botão Parar.
  • Resumo operacional com status, progresso percentual, total previsto, linhas processadas e Task ID.
  • Atualização de status/logs a cada 2 segundos (polling).
  • Auto-scroll dos logs com opção para ativar/desativar.

2.2 Backend/API

  • POST /api/jobs/cotacoes para criar job de processamento.
  • GET /api/jobs/{task_id} para status e progresso.
  • GET /api/jobs/{task_id}/logs para leitura incremental de logs com cursor.
  • GET /health para healthcheck.
  • GET /manual-de-uso para abrir este manual.
  • Serviço de arquivos estáticos do frontend buildado (SPA com fallback para index.html).

2.3 Processamento assíncrono

  • Fila RQ com Redis para execução de jobs.
  • Mapeamento de status da fila para status da UI: PENDING, STARTED, SUCCESS, FAILURE.
  • Logs por task em /app/data/jobs/{task_id}.log.
  • Uploads em /app/data/uploads.

3) Regras de entrada e validações

Responsável: Dados e Qualidade
  • Formato aceito no upload: somente .xlsx.
  • Tamanho máximo do arquivo: 20 MB.
  • Upload em chunks de 1 MB para reduzir risco de estouro de memória.
  • Arquivo vazio é rejeitado.
  • Campos obrigatórios na API/UI: usuário, senha, data de referência e planilha.

3.1 Regras da planilha

  • Cabeçalho esperado na linha 3.
  • Processamento limitado às primeiras 100 linhas após o cabeçalho (configuração atual).
  • Linhas sem valor na coluna Número são ignoradas.
  • Cabeçalhos obrigatórios: Número, Perfil e Base.
  • Coluna de frete é encontrada pelo texto da data de referência informado pelo usuário (na linha de cabeçalho).

3.2 Mapeamento de campos da automação

Origem Destino no formulário Regra
Coluna Número Nº e Nº Pedido Cliente Mesmo valor nos dois campos
Entrada do usuário Validade Usa a data da cotação convertida para dd/mm/aaaa
Coluna Perfil Categoria Veículo Seleciona por label
Coluna Base Remetente Busca opção pelo padrão de cidade no texto da opção
Cruzamento por data Frete Negociado Lê a célula da coluna da data selecionada
Colunas Nome + Placa + data Obs. Interna Formato: Motorista: X | Placa: Y | Data: Z

3.3 Regras fixas aplicadas durante o preenchimento

  • Agência: LOGTUDO MATRIZ - BAHIA.
  • Status: Aprovado Cliente.
  • Regra de frete: COTAÇÃO LATAM.
  • Operação: Carga fechada.
  • Pagamento de frete: rádio com value R.
  • KM preenchido com valor aleatório entre 50 e 100.
  • UF inicial copiada para UF final.
  • Cidade inicial copiada para pesquisa de cidade final.

4) Fluxo operacional (passo a passo)

Responsável: Operação
  1. Abra o app no caminho configurado (ex.: /cotacoes/).
  2. Preencha usuário, senha e data da cotação.
  3. Selecione a planilha .xlsx.
  4. Clique em Iniciar.
  5. Acompanhe status e logs em tempo real.
  6. Ao final, valide se o status ficou SUCCESS e revise os logs de conclusão.

5) Logs e progresso

Responsável: Plataforma
  • O progresso é inferido pelos logs: cada ocorrência de Processando linha incrementa linhas processadas.
  • O total previsto vem da mensagem Total de linhas elegíveis para automação.
  • Em caso de erro, o traceback é gravado no log da task.

7) Configurações técnicas do app

Responsável: Plataforma
  • Seletores e URLs da automação: automacao/config/selectors.json.
  • Mapa formal de campos: automacao/config/form_mapping.json.
  • Conectividade Playwright em VPS: pasta Conectividade/ com seccomp e compose dedicados.

8) Solução de problemas

Responsável: Suporte
  • Erro 400 no upload: confirme extensão .xlsx e campos obrigatórios.
  • Erro 413: arquivo acima de 20 MB.
  • Falha de login: revise usuário/senha informados na tela.
  • Sem progresso no job: valide saúde de redis, app e rq-worker.
  • Remetente não encontrado: revise conteúdo da coluna Base e opções disponíveis no portal.
  • Erro de cabeçalho: garanta linha 3 com Número, Perfil, Base e coluna da data informada.
Recomendação operacional: valide uma pequena amostra da planilha antes de processar lotes maiores e acompanhe os logs da task até o status final.
